# AIOS Travel CRM — 20-Phase Delivery Plan

## Product outcome

AIOS is a secure, multi-tenant travel operating system for travel teams. It unifies customer conversations, leads, sales, itinerary creation, bookings, trip operations, supplier work, payments, knowledge, and approval-first AI agents.

The current repository contains a working CRM foundation, Supabase authentication and tenant isolation, a durable approval ledger, a model-provider router, and bounded AIOS lead-intake and itinerary-drafting workflows. The global shell, central Opportunity Workspace, detail-first Itinerary Studio, focused Trip Operations, and operational Finance workspace passes are complete after an August 2026 review found that strong underlying capabilities were being presented as disconnected feature landing pages. It is not yet a production-complete travel operating system. This plan records the real delivery state and turns the remaining work into explicit release gates.

## Non-negotiable principles

- **Human authority:** AI can prepare, recommend, and automate low-risk internal work. It cannot send external communications, change prices, confirm bookings, or process money without a policy check and approval.
- **Tenant isolation:** Every customer-owned record belongs to an organization; database row-level security is the enforcement layer.
- **Auditability:** Important business, AI, and privileged actions create immutable audit events.
- **Security before convenience:** Secrets are server-only; sensitive documents are private; least privilege and secure defaults win over speed.
- **One source of truth:** Supabase migrations define the schema. Generated database types are used by the application. Do not introduce a second ORM/schema authority.
- **Mobile-ready operations:** Key approvals, inbox triage, and on-trip actions must be usable on a phone.
- **Approval is non-bypassable for external effects:** An organization may tune AIOS autonomy only within the action's safety class. Customer/supplier messages, documents, price changes, bookings, and payments can never be changed to Auto.
- **Model-agnostic control plane:** GLM-4.7-Flash is allowed for disposable development fixtures; production models are selected per task only after data-handling, quality, cost, and fallback policies have been approved.

## UX hardening release plan — 12 August 2026

This release improves clarity, readability, responsiveness, and daily operating speed without changing CRM records, authorization rules, AIOS policies, or external-effect approval gates. Each batch must retain the existing action payloads and pass lint, type checking, behavioral tests, production build, and focused browser regression checks.

### Stage 1 — Shared foundations

- Raise operational metadata and control text to a readable floor while preserving compact density.
- Replace low-contrast neutral text with accessible shared tokens.
- move product help into the application header on desktop and a safe compact position on mobile so it never covers workspace controls.
- Replace misleading identity placeholders with a neutral loading state and remove duplicated workspace-context reads where safely possible.
- Remove visible encoding corruption from application, authentication, AIOS, Knowledge, proposal, and onboarding copy.

### Stage 2 — High-impact screen defects

- Repair Analytics desktop overflow, constrain chart/table widths, and introduce a compact leadership summary so the page can be scanned before deeper analysis.
- Remove the nested itinerary workspace scrollbar, make the selected draft state explicit, and distinguish a genuinely empty plan from unavailable or mismatched itinerary data.
- Replace tenant-visible server environment terminology in Integrations with role-appropriate recovery guidance.
- Make AIOS counts grammatically correct and remove decorative characters from the accessibility tree.

### Stage 3 — Daily workflow efficiency

- Move the active conversation workspace ahead of secondary Inbox configuration and collapse optional setup areas by default.
- Keep Task cards scannable by revealing secondary controls on focus, selection, or explicit expansion.
- Add one unambiguous Quote readiness summary and primary next action.
- Expand AIOS Activity to a useful ledger with filtering and record detail, and make the Approvals empty state educational without consuming the viewport.

### Stage 4 — Administration and account clarity

- Replace Sales Workflow punctuation syntax with structured qualification-item and sequence-step rows while preserving the existing server payload format.
- Clarify password requirements and recovery-session states.
- Remove hard-coded demo-agency language from generic authentication and onboarding screens.
- Give expired or invalid private customer links a deliberate, non-disclosing branded state instead of an unexplained dead end where the security contract permits it.

### Stage 5 — Visual and responsive unification

- Apply one operational surface, border, typography, density, focus, and status-token system across CRM, intelligence, AIOS, and administration screens.
- Retain dark or editorial styling only for bounded insight panels and customer-facing experiences.
- Validate 1280px desktop, 768px tablet, and 390px mobile layouts with keyboard navigation and zero horizontal document overflow.

### Stage 6 — Release verification

- Run lint, TypeScript, all behavioral tests, AI evaluations, production build, dependency/security checks, and deployment readiness.
- Run focused browser checks for global navigation, every principal route, lead-to-trip handoff, approval handling, integration drawers, public capture, proposal acceptance, and traveller portal boundaries.
- Record any deferred operator research or external-service setup separately; do not mark it as a code defect.

### Cross-phase CRM workspace UX refactor

**Goal:** Make AIOS behave like one travel-business operating workspace used throughout the day, with AI embedded in the work and implementation machinery progressively disclosed.

**Delivered in the current refactor:** One persistent authenticated shell now owns every principal route. `/leads` is no longer a missing or query-only destination. Primary navigation is grouped into Run the business, AI work, and Administration concerns. Principal modules use compact operational headers; creation, import, template, commercial-policy, and advanced configuration tools sit behind intentional drawers; repeated hero copy, lifecycle ribbons, governance slogans, and per-page navigation have been removed from the first viewport. Home begins with live attention counts and a real New/Qualified/Proposal/Decision pipeline summary instead of a decorative trend graphic. Contacts is directory-first with operational columns, Inbox becomes a three-pane list/conversation/context workspace on desktop, and Tasks keeps its board dominant. Quotes now provides a compact record selector and one active commercial-document workspace instead of expanding every editor for every quote. The Opportunity Workspace now opens with AIOS's evidence-linked next action, traveller/owner/value/travel facts, a Captured → Qualified → Itinerary → Quote → Committed → Operate journey, overdue and missing-information signals, and counts of linked conversations, tasks, quotes, and trip drafts. Its Conversation, Quotes, and Itinerary handoffs carry the deal identity; each destination selects or focuses the matching record, and new itinerary drafts inherit the opportunity link. The selected Itinerary workspace is now a dated, day-first canvas rather than a flat item list: it shows every planned and empty trip day, structures each item by time/type/title/location, keeps the readiness summary visible, and provides an inline quick-add action while templates and creation remain progressively disclosed. Optional start/end times and location now persist through the role-checked, row-locked append RPC. Planners enter local wall time plus an explicit IANA trip/item zone; PostgreSQL converts it to an exact instant, stores the zone snapshot, rejects invalid/nonexistent local times, and prevents new timed rows without zone evidence. Existing ambiguous timed rows remain visibly review-required instead of receiving a guessed zone. Planners can move items earlier or later without deleting evidence; a second guarded RPC shares the same short trip-row serialization lock, swaps only adjacent positions within one day, and returns the authoritative order to the canvas. The focused hosted contract verifies exact converted timestamps, zone/location evidence, and persisted sequence. Trips, Finance, and Knowledge share the neutral CRM canvas and record-summary treatment, reserving dark panels for exception monitoring or AI context. Trip detail derives one operations priority from live exception, manifest, entry, service, task, document, and lifecycle evidence. Finance now opens on one actionable AIOS priority, the balances behind it, receivable/payable/overdue/approval counts, currency-separated exposure, and compact section navigation before its supplier, invoice, provider, and accounting machinery. AIOS exposes Manual, Assisted, and Autopilot first, then groups granular policies by business area and moves provider/queue controls under Advanced. Navigation and mutation controls are workspace-role-aware, non-operating users receive one shared view-only pattern, and the header shows the live AI operating mode. ## Cross-phase release gates

No phase may be marked complete unless it includes:

1. Typed domain models and migration/repository changes where data is involved.
2. Authorization and RLS verification for any tenant-owned or sensitive data.
3. Empty, loading, error, permission-denied, and mobile states.
4. Audit events for high-impact actions.
5. Tests proportional to the risk of the change.
6. Documentation for user-visible behavior and operational support.
7. Product-owner acceptance against its phase exit gate.

## Suggested implementation cadence

- **Stabilization release (current):** The local engineering slice—source-control initialization, reproducible schema/seed/types, database-advisor remediation, Auth parity, responsive dashboard/AIOS fixes, authenticated browser coverage, and CI migration validation—is complete. The release still waits on credential rotation, external email setup, environment separation, observability, and broader acceptance evidence.
- **CRM release:** Complete Phases 07–09 with real customer/activity/inbox data, not placeholder dashboard modules.
- **AI-assisted sales release:** Complete Phases 10–13 with tool contracts, evaluation gates, and approval-first external actions.
- **Travel operations release:** Phases 14–16.
- **Intelligence and launch release:** Phases 17–20.

This sequence intentionally makes AIOS trustworthy before it becomes powerful. The first agent already proves the desired operating model—AIOS can analyse and propose, a human can selectively accept, and low-risk follow-up work can proceed only inside policy. Each new agent must earn broader authority through the same evidence, policy, and audit gates.
