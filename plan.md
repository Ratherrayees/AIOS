# AIOS Travel CRM — 20-Phase Delivery Plan

## Product outcome

AIOS is a secure, multi-tenant travel operating system for travel teams. It unifies customer conversations, leads, sales, itinerary creation, bookings, trip operations, supplier work, payments, knowledge, and approval-first AI agents.

The current repository contains a polished, working CRM foundation, Supabase authentication and tenant isolation, a durable approval ledger, a model-provider router, and bounded AIOS lead-intake and itinerary-drafting workflows. It is not yet a production-complete travel operating system. This plan records the real delivery state and turns the remaining work into explicit release gates.

## Non-negotiable principles

- **Human authority:** AI can prepare, recommend, and automate low-risk internal work. It cannot send external communications, change prices, confirm bookings, or process money without a policy check and approval.
- **Tenant isolation:** Every customer-owned record belongs to an organization; database row-level security is the enforcement layer.
- **Auditability:** Important business, AI, and privileged actions create immutable audit events.
- **Security before convenience:** Secrets are server-only; sensitive documents are private; least privilege and secure defaults win over speed.
- **One source of truth:** Supabase migrations define the schema. Generated database types are used by the application. Do not introduce a second ORM/schema authority.
- **Mobile-ready operations:** Key approvals, inbox triage, and on-trip actions must be usable on a phone.
- **Approval is non-bypassable for external effects:** An organization may tune AIOS autonomy only within the action's safety class. Customer/supplier messages, documents, price changes, bookings, and payments can never be changed to Auto.
- **Model-agnostic control plane:** GLM-4.7-Flash is allowed for disposable development fixtures; production models are selected per task only after data-handling, quality, cost, and fallback policies have been approved.

A curator can prepare a successor draft from an approved source, clone its citations, revise or remove passages only while the successor remains Draft, and send the replacement through human review; approving it atomically retires the superseded version, preserves explicit lineage, and avoids a retrieval gap. Competing active successors are rejected. Ordinary members can read and search only approved normal-sensitivity material; restricted content remains curator-only, drafts never enter retrieval, retired sources disappear immediately, and expired review dates are returned explicitly as stale. Full-text retrieval is tenant- and permission-aware and returns the exact source, version, authority, link, citation label, excerpt, relevance, and freshness state. Conflict Watch compares current approved passages with the same normalized heading and source kind, flags differing date/number/currency tokens, shows both cited passages side by side, and requires a curator evidence note to confirm or dismiss the signal; it never selects a source as correct, and confirmed conflicts resolve only after competing evidence leaves current retrieval through the normal lifecycle. The Answer Desk sends only current permitted evidence through the governed provider router, requires structured claims tied to exact retrieved passage IDs, validates lexical and date/number support, attaches authoritative citations server-side, records a durable job/run with token-cost telemetry, and escalates high-impact visa/passport/immigration/legal/medical/refund/payment/price/booking topics to a human. Unsupported or stale-only questions receive an explicit deterministic refusal without a provider call. Question and source text are treated as untrusted input, prompt-like content is blocked, and direct identifiers are redacted before model use. Local verification covers import/lifecycle/renewal/conflict boundaries, permission-aware retrieval, grounding/citation attacks, invented facts, model-input safety, high-impact escalation, zero-provider refusal, durable metadata-only jobs, and the complete browser workflow. A fictional non-CRM GLM-4.7-Flash smoke test confirms the provider adapter accepts the structured answer contract. Remaining scope is PDF/DOCX parsing, encrypted raw-file retention where needed, richer destination/supplier import tools, pgvector-backed semantic retrieval where lexical retrieval is insufficient, richer semantic conflict detection, bulk freshness policy, staged deployment, and product-owner acceptance.

**Exit gate:** Users can ask a policy or supplier question and receive a tenant-permitted, cited answer that links to the source material.

## Cross-phase release gates

No phase may be marked complete unless it includes:

1. Typed domain models and migration/repository changes where data is involved.
2. Authorization and RLS verification for any tenant-owned or sensitive data.
3. Empty, loading, error, permission-denied, and mobile states.
4. Audit events for high-impact actions.
5. Tests proportional to the risk of the change.
6. Documentation for user-visible behavior and operational support.
7. Product-owner acceptance against its phase exit gate.
